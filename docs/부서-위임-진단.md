# 업무 보드 진단 · '부서에 큰 일을 맡기면 전문가 에이전트에게 위임' 요구 대비

2026-11-25 · 기준 소스 v0.1.356 (`d8cc427`) · 작업 브랜치 `claude/agent-departments`

## 결론

현재 업무 보드에는 위임 기능이 없습니다.
보드는 사용자가 카드 한 장마다 에이전트 한 명을 직접 고르는 대기열입니다.
그 에이전트는 다른 전문가를 부를 수 없도록 막혀 있습니다.
'부서'와 '비서실장'은 화면 표시용 이름일 뿐이고 실행 주체가 아닙니다.
GPT 작업은 원하신 '부서장이 쪼개서 맡기는 구조' 대신, '카드 한 장 = 에이전트 한 명'을 전제로 결재·권한·보고서 절차를 다듬는 데 집중됐습니다.

## 문제점

### 1. 부서장(배분·취합 담당)이 실제로 존재하지 않음

- 조직도는 '대표 (결재) → 비서실장 · 배분·취합 → 팀' 순서로 그려집니다. (`src/renderer/src/dashboard/WorkBoard.tsx:519-520`)
- 그런데 '비서실장'은 고정 문자열입니다. 일을 나누거나 결과를 모으는 에이전트가 없습니다.
- 실제 '배분기'는 대기열 순서대로 카드를 꺼내 실행하는 타이머입니다. (`src/main/workBoard.ts:756-778`)
- 동시 실행 기본값은 1건입니다. (`src/main/workBoard.ts:14`)

### 2. 담당자는 사용자가 카드마다 직접 지정

- 지시 입력 양식에서 '담당 에이전트'를 사용자가 한 명 고릅니다. (`WorkBoard.tsx:323`)
- 비워 두면 기본 세션 하나가 혼자 수행합니다.
- 큰 일을 맡기려면 사용자가 미리 여러 건으로 쪼개고 담당자를 각각 정해야 합니다. '일괄 지시' 기능도 이 쪼개기를 사용자에게 맡기는 구조입니다.

### 3. 실행 중인 에이전트가 다른 에이전트를 부를 수 없음

보드 실행기의 세션 설정은 다음과 같습니다. (`src/main/workBoardRunner.ts:287-290`)

- `tools: []`: 하위 에이전트를 부르는 내장 `Agent` 도구가 꺼져 있습니다.
- `agents: { [담당자 1명] }`: 세션에 등록되는 정의가 담당자 본인뿐입니다.
- `skills: []`, `plugins: []`, `settingSources: []`: 사용자 스킬과 플러그인을 쓸 수 없습니다.

따라서 '팀장 에이전트'를 정의해 두어도 팀원에게 일을 넘길 수 없습니다.

### 4. 팀 구성이 사건 업무와 무관한 고정 목록

- 보드를 처음 만들 때 `teams.yaml`에 기본 팀 6개를 씁니다. (`src/main/workBoardStore.ts:13-20`)
- 6개 팀: 준법감시, 법무팀, 콘텐츠팀, 마케팅팀, 영업·홍보팀, 플랫폼운영팀.
- 팀은 화면 그룹일 뿐입니다. 카드를 '팀'에게 맡기는 기능은 없습니다.
- 팀원 이름도 `~/.claude/agents`에 실제 정의가 있는지 확인하지 않습니다. 이 Windows PC에는 그 폴더가 없습니다.

### 5. 외부 도구를 한 번 요청하면 업무 전체가 멈춤

- 담당자가 Bash나 MCP 도구를 요청하면 즉시 세션을 끊고 '결재 필요'로 멈춥니다. (`workBoardRunner.ts:130-140`)
- 읽기 전용 조회도 마찬가지입니다. 11월 25일 04:18·04:19 `list_todos` 중단 사례가 이 경우입니다.
- 쓸 수 있는 MCP는 보드 파일 도구와 쥬리서포트 할일 조회뿐입니다. `korean-law`(법령·판결 조회)는 연결되지 않습니다. (`workBoardRunner.ts:291-297`)
- 그래서 여러 단계로 된 큰 일은 첫 외부 도구에서 멈춥니다. '맡기고 자리를 비우는' 사용 방식이 성립하지 않습니다.

### 6. 문장 어미로 실행 경로를 가름

- '쥬리서포트 할일을 정리해 줘'와 '정리한다'가 서로 다른 경로로 갑니다. 정규식이 동사 어미를 판별합니다. (`src/shared/workBoard.ts:10-21`)
- '확인 필요' 버튼 표시도 한국어 진행 기록 문자열을 역추적해 정합니다. (`src/shared/workBoard.ts:99-111`)
- 인계서도 이 한계를 인정합니다. ("동사 어미를 하나 더 추가하면 이 차이는 남습니다.")

### 7. 개발 노력의 방향

- v0.1.356까지 208개 커밋이 올라갔고, 그중 21개 이상이 보드·할일·결재·보고 관련입니다. (`git log e46b831..d8cc427`)
- 대부분 할일 조회 동의 파일, 판본 해시, 관리권 인계, 중단 사유 판별에 쓰였습니다.
- 위임 구조에 관한 커밋은 없습니다.

## 그대로 살릴 부분

아래 기능은 '대표 결재' 층으로 그대로 쓸 수 있습니다.

- 보고서함: 수신 확인, 추가 업무 지시
- 결재함: 최종안 승인, 승인 후 실행, 반려, 수정 요청
- 문서 열람·다운로드
- 재시작 복구, SSH 실행, 다른 PC 관리권 인수

인계서 3~4절의 화면 개선 과제는 위임 구조 위에서 다시 정리하면 됩니다.

## 제안 구조

1. **부서 정의**: `teams.yaml`의 각 팀에 `lead`(부서장)와 `members`(전문가)를 둡니다. 기본 팀은 송무 업무에 맞게 바꿉니다. 예: 송무팀(사실관계·법리·서면), 리서치팀, 사무관리팀.
2. **부서에 지시**: 카드의 담당을 '사람 한 명'이 아니라 '부서'로 고를 수 있게 합니다. 담당을 비우면 비서실장이 부서를 고릅니다.
3. **부서장 실행**: 부서장 세션에 팀원 정의를 모두 등록하고 `Agent` 도구를 켭니다. 부서장이 팀원에게 일을 나눠 맡기고 결과를 모아 보고서 하나를 씁니다.
4. **읽기 도구 사전 허용**: 부서별로 읽기 전용 도구(파일 읽기, 쥬리서포트 조회, `korean-law` 조회)를 미리 허용합니다. 결재는 쓰기·발송·외부 실행에만 받습니다.
5. **보드 표시**: 팀원별 진행 상황을 같은 카드의 기록에 표시합니다. 결과는 기존 보고서함·결재함으로 보냅니다.

### 결정이 필요한 사항

- **위임 방식**
  - (가) 부서장이 한 세션 안에서 팀원을 하위 에이전트로 부르는 방식: 구현이 짧습니다. 카드 하나에 진행 기록이 쌓입니다.
  - (나) 부서장이 계획을 세우면 보드가 팀원별 하위 카드를 만들고, 모두 끝나면 부서장이 취합하는 방식: 보드에 팀원 카드가 보이고 재시작에 강합니다. 구현량이 큽니다.
- **기본 부서 구성**: 어떤 부서와 전문가를 기본으로 둘지 정해야 합니다.

## 구현 결과 (2026-11-25, 브랜치 `claude/agent-departments`)

결정 사항: 위임은 **전문가별 하위 카드** 방식, 부서 구성은 **사용자가 직접** 정한다.

### 동작 순서

1. 사용자가 업무 보드 오른쪽 조직도의 **부서 관리**에서 부서를 만든다. 부서마다 이름·색상·부서장·부서원을 정한다.
2. 지시 입력의 **담당**에서 부서를 고른다. 일괄 지시와 추가 업무 지시에서도 같다.
3. 부서장 세션이 `assign_members` 도구로 업무를 부서원별 하위 업무로 나눈다. 앞 단계 결과가 필요한 업무는 `after`로 순서를 정한다.
4. 보드가 부서원마다 하위 카드를 만든다. 부서 지시는 '부서원 수행 중' 상태로 기다린다.
5. 부서원은 각자 독립 세션에서 수행한다. 선행 하위 업무의 보고서와 부서 지시 원문을 참고자료로 받는다.
6. 하위 업무가 모두 완료되면 부서장 세션이 다시 실행되어 부서원 보고서를 취합하고 최종 보고서를 쓴다.
7. 최종 보고서는 기존 흐름대로 보고서함 또는 결재함에 도착한다. 하위 카드의 보고서는 보고서함에 들어가지 않는다.

부서장이 혼자 처리할 만한 작은 업무는 배분하지 않고 직접 보고서를 쓴다.
하위 업무 하나가 '확인 필요'로 멈추면 부서 지시는 계속 기다린다. 그 하위 카드를 처리하면 이어서 진행한다.

### 남은 일

- 동시 실행 수 기본값이 1이다. 부서원을 동시에 돌리려면 업무 보드 설정에서 동시 실행 수를 올려야 한다.
- 부서원이 Bash나 외부 MCP(korean-law 등)를 요청하면 지금도 그 하위 카드가 멈춘다. 읽기 전용 도구를 부서별로 미리 허용하는 기능은 아직 없다.
- 인계서 3~4절의 화면 개선(확인 필요 카드 문구, 결재 문서 판본 고정 등)은 이번 범위에 넣지 않았다.
- 실제 운영 계정과 실제 에이전트 정의로는 실행해 보지 않았다.
