# 작업일지 기능정의 (확정 · 2026-11-26)

작성 2026-11-26 · 결정 6개 변호사 확정 2026-11-26 · 시안: [작업일지 시안](https://claude.ai/artifact/QUNjcmfQMsPdmLf5ukaJAv) (목록 화면, 세션 상세 화면)

## 0. 목적

"어떤 세션을 열어서 무슨 일을 했는지 모르겠다"를 푼다. 대화창에서 연 세션, 업무 보드 카드, 부서가 연 세션을 한 화면에 모아 **언제·어디서·누가·무엇을 시켰고·무엇을 했고·어떤 파일이 바뀌었고·끝났는지**를 한 줄로 보여 준다.

부서는 작업일지의 분류 기준으로 쓴다. 부서가 없어도 작업일지는 그대로 동작한다. 부서 자체의 정의는 [부서-기능정의.md](부서-기능정의.md)를 따른다.

## 1. 지금 있는 것

사건 대시보드 안의 작업일지(`src/renderer/src/dashboard/WorkLogView.tsx`, `src/main/workLogData.ts`).

| 항목 | 현재 | 출처 |
|---|---|---|
| 범위 | 최근 30일(180일까지 더 보기), 로컬과 SSH 서버의 Claude 대화 기록 | `~/.claude/projects` 대화 기록 스캔, `worklog-scan.json` 캐시 |
| 줄 단위 | 세션 × 날짜. 한 세션을 여러 날 쓰면 날마다 한 줄 | 메시지 시각 |
| 보이는 것 | 마지막 시각, 사건번호·사건명(또는 폴더명), 세션 제목, 그날 첫 지시와 지시 수, SSH 표시, 자동 요약 | 세션 메타 |
| 자동 요약 | 앱 대화 세션만. 마지막 응답 90초 뒤 작은 모델 1회로 "한 일/다음 할 일" 생성. 가장 최근 날짜 줄에만 표시 | `agent-service.ts` |
| 동작 | 클릭하면 세션 이어서 열기, Ctrl/⌘ 클릭은 새 탭 | |

빠진 것:

- **결과가 안 보임:** 바뀐 파일, 완료/중단 여부, 비용이 없다.
- **보드 세션이 섞임:** 업무 보드 카드도 사건 폴더에서 Claude 세션 기록을 남기므로(세션 저장을 끄지 않음) 작업일지에 섞여 나올 것으로 보인다(실제 화면은 미확인). 나오더라도 일반 대화와 구분이 없고, 첫 지시 자리에 앱이 조립한 긴 프롬프트가 보인다. 카드가 끝나면 카드에서 `sessionId`를 지우므로 카드와 세션을 다시 이을 수 없다.
- **비용 미보관:** 대화 세션 비용은 실행 중 계산(`costUsdFromModelUsage`)만 하고 저장하지 않는다. 카드는 `cost`를 저장한다.
- **Claude 외 제공자 없음:** Codex, Antigravity 세션은 작업일지에 나오지 않는다.
- **찾기 어려움:** 사건 대시보드 안에 있어 하루를 돌아볼 때 바로 떠오르는 자리가 아니다.

## 2. 화면

### 2.1 목록

- **위치:** 작업공간과 무관한 독립 화면. 왼쪽 활동 막대(또는 상단)의 **작업일지** 버튼으로 연다. 사건 대시보드의 기존 작업일지는 이 화면을 사건으로 거른 보기로 바꾼다.
- **필터:** 기간(오늘 / 이번 주 / 최근 30일), 부서(전체 / 부서별 / 부서 없음·미확정), 상태(전체 / 완료 / 하다 만 일 / 결재 대기), 사건, "추천 부서도 포함해 집계" 켜기·끄기.
- **요약 숫자:** 세션 수, 완료, 하다 만 일, 결재 대기, 비용. 필터를 따라 바뀐다.
- **세션 한 줄:**

| 칸 | 내용 |
|---|---|
| 언제 | 시작–끝 시각, 걸린 시간 |
| 어디서 | 사건번호·사건명(사건이 없으면 폴더명), 로컬 / SSH 서버 이름 |
| 누가·부서 | 일반 대화 / 업무 보드 카드 / 정기 업무 / ○○부서 부서장·부서원, 그리고 부서 칩(3장) |
| 시킨 일 → 한 일 | 첫 지시와 "외 지시 n건", 한 일 요약, 만들거나 고친 파일(누르면 열기) |
| 상태·비용 | 완료 / 하다 만 일 / 결재 대기, 비용, [세션 열기], 하다 만 일이면 [○○부서에 이어서 맡기기] |

- **보드 묶음:** 자동 배분(비서실장)이나 부서 지시는 원 카드 한 줄 아래에 부서장·부서원 세션을 들여써서 묶는다. 묶인 세션은 따로 한 줄씩 다시 나오지 않는다.

### 2.2 세션 상세

목록에서 줄을 누르면 오른쪽에 열린다.

- 사건, 시각, 누가, 지시 수
- **부서:** 현재 부서와 표시 종류(직접 지정 / 추천 확정 / 추천 / 카드 담당 / 부서 없음), 추천이면 추천 이유와 [○○으로 확정] [다른 부서 선택] [해당 부서 없음]
- 시킨 일 전체(시각 포함), 한 일 요약, 만들거나 고친 파일(경로, 새로 만듦/수정, 열기)
- 상태, 비용, 모델
- [세션 이어서 열기], [이 결과로 부서에 후속 업무 맡기기](업무 보드에 새 카드, 이 세션 요약을 참고자료로 첨부)

## 3. 부서 표시: 직접 지정과 추천

| 종류 | 언제 생기나 | 표시 | 바뀌나 |
|---|---|---|---|
| 카드 담당 | 업무 보드 카드·정기 업무·부서원 세션 | 진한 칩 · "카드 담당" | 카드의 `team`을 그대로 쓴다. 추측하지 않는다 |
| 직접 지정 | 대화 입력창 옆 부서 선택, 또는 작업일지에서 고름 | 진한 칩 · "직접 지정" | 사람이 바꿀 때만 |
| 추천 확정 | 추천에서 [확정]을 누름 | 진한 칩 · "추천 확정" | 사람이 바꿀 때만 |
| 추천 | 부서가 정해지지 않은 대화 세션의 요약을 만들 때 | 점선 칩 · "추천" + [확정] [변경] | 다음 요약 때 다시 추천할 수 있다 |
| 부서 없음 | 맞는 부서가 없다고 판단하거나 사람이 [해당 부서 없음]을 고름 | 회색 글씨 | 사람이 고른 것은 유지 |

규칙:

1. 사람이 정한 것(직접 지정, 추천 확정, 해당 부서 없음)은 추천이 덮어쓰지 않는다.
2. 추천은 기존 요약 호출에 질문을 하나 더 붙여 만든다. 근거는 부서 `description`이다. 추가 모델 호출은 없다.
3. 부서가 하나도 없으면 추천하지 않는다.
4. 추천은 이유 한 줄을 함께 저장한다. 상세 화면에 그대로 보인다.
5. 집계에서 추천을 넣을지는 필터의 "추천 부서도 포함해 집계"로 고른다. 끄면 추천 세션은 "부서 없음·미확정"으로 센다.
6. 대화에서 부서를 고르면 **분류 표시만** 바뀐다. 그 부서의 규칙이나 도구 권한은 대화에 적용하지 않는다(결정 2, 확정).

## 4. 상태 판정

| 상태 | 기준 |
|---|---|
| 완료 | 마지막 턴이 정상 종료. 카드는 `done`·`reported` |
| 하다 만 일 | 사용자가 중지함, 오류나 연결 끊김으로 끝남, 카드가 `blocked`·`failed` |
| 결재 대기 | 카드가 `awaiting_approval` |
| 진행 중 | 지금 실행 중인 세션·카드 |

마지막 응답이 질문으로 끝났는지 같은 추측성 기준은 쓰지 않는다(결정 3).

## 5. 저장할 데이터와 출처

| 항목 | 대화 세션 | 업무 보드 세션 | 바꿀 곳 |
|---|---|---|---|
| 시각·사건·위치 | 지금 있음 | 지금 있음 | |
| 첫 지시 | 지금 있음 | 카드 제목·본문 | 보드 세션은 조립된 프롬프트 대신 카드 내용을 보여 준다 |
| 한 일 요약 | 지금 있음(최근 날짜만) | 카드 보고서의 결론 첫 문단 | 날짜별 요약은 2단계 |
| 바뀐 파일 | 없음 | 없음 | 대화 기록의 Write·Edit·MultiEdit·NotebookEdit 도구 호출과 앱의 문서 내보내기에서 경로를 모은다. Bash로 만든 파일은 못 잡을 수 있다고 상세 화면에 표기 |
| 상태 | 없음 | 카드 상태 | 대화는 마지막 턴의 종료 사유를 세션 메타에 저장 |
| 비용 | 계산만 함 | 카드 `cost` | 대화 세션 비용을 세션 메타에 누적 저장 |
| 부서 | 없음 | 카드 `team` | 세션 메타에 `department`, `departmentSource`(direct/confirmed/suggested/none), `departmentReason` |
| 카드 ↔ 세션 | 해당 없음 | 끝나면 끊김 | 카드에 실행한 세션 ID 목록을 남긴다(현재는 끝나면 `sessionId`를 지움) |

세션 메타는 기존 `rememberSessionMeta`(`src/main/sessions.ts`)를 넓혀 쓴다. SSH 세션의 메타도 지금처럼 로컬 앱에 저장한다.

## 7. 단계

**1단계 · 무엇을 했나가 보이게**
- 독립 화면, 필터, 요약 숫자
- 세션 줄: 상태, 비용, 바뀐 파일
- 보드 세션 구분과 카드 묶음(카드에 세션 ID 보관)
- 세션 상세 화면

**2단계 · 부서와 연결**
- 부서 추천(요약 호출에 포함), 확정·변경·해당 부서 없음
- 대화 입력창 옆 부서 선택(표시만)
- 하다 만 일 → [○○부서에 이어서 맡기기], 세션 상세 → [이 결과로 부서에 후속 업무 맡기기]
- 부서장이 저녁 정기 업무로 그날 자기 부서 세션을 정리(부서 일일 보고)

**3단계 · 정확도와 범위**
- 날짜별 한 일 요약
- 추천을 고친 기록을 다음 추천의 예시로 사용
- Codex·Antigravity 세션
- 부서 월 사용량에 대화 세션 비용 합산

## 9. 1단계 구현 결과 (2026-11-26)

**화면**
- 상단 **작업일지** 버튼(업무 보드 옆)으로 여는 독립 화면 `.work-log-window`. 기간(오늘·최근 7일·최근 30일), 상태, 사건 필터와 요약 숫자(세션·완료·하다 만 일·결재 대기·비용).
- 세션 한 줄: 시작–끝·걸린 시간, 사건·로컬/SSH, 누가(일반 대화 / 업무 보드 · …), 첫 지시와 지시 수, 한 일, 바뀐 파일(누르면 문서 창, SSH는 `ssh://프로필/경로`), 상태·사유, 비용.
- 줄을 누르면 오른쪽 상세: 그날 지시 전체(시각), 한 일, 하위 업무, 파일 목록과 열기, 상태·비용·모델, [업무 보드에서 보기] [세션 이어서 열기].
- 사건 대시보드의 📅 작업일지도 같은 컴포넌트(`WorkLogView`)의 좁은 보기로 상태·비용·파일·보드 묶음을 함께 보인다.

**데이터**
- 대화 기록 스캔(`daysFromTranscriptContent`, 원격은 같은 규칙의 Python 스크립트)이 날짜별 첫 지시 시각, Write·Edit·MultiEdit·NotebookEdit로 바꾼 파일, 세션의 마지막 상태(정상 종료 / 사용자 중지 / 오류 / 턴 미종료)를 모은다. 스캔 캐시 버전 3. 슬래시 명령 출력 줄은 상태 판단에서 뺀다.
- 상태: 턴이 끝나지 않은 채 10분이 지나면 '응답 없이 끊김'. 세션을 다음 날 이어 썼으면 이전 날짜 줄은 '이어서 진행'.
- 대화 세션 비용: 턴마다 결과의 `total_cost_usd`를 세션 메타 `costByDay`(날짜별, 90일)에 더한다. 앱 밖에서 돌린 세션은 비용이 없다.
- 업무 보드 카드는 실행한 세션 ID를 `sessions`(최대 50개)에 남긴다. 작업일지는 열린 보드의 카드(`WorkBoard.workLogCards`)를 받아, 그 세션들을 원 지시 카드 한 줄로 묶고 하위 카드(부서장·부서원·승인 후 실행)를 아래에 둔다. 한 일은 원 지시 보고서의 결론 첫 문단, 비용은 묶음 전체 합.

**검증**
- `verify:case-activity`: 파일 수집·마지막 상태·상태 판정·비용·보드 묶음·자정 무관
