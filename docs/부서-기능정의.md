# 부서 기능 정의 (확정 · 2026-11-25)

2026-11-25 · 기준 소스 v0.1.357 (`47dc175`) · 입력: 「전문가(서브에이전트) 기능의 역할 — 부서 기능 설계용 설명」(2026-11-25)

## 0. 목표

변호사가 legal-terminal 앱에 일을 맡기면 사무소의 부서처럼 처리된다.

- 변호사는 **대표**다. 지시하고, 보고서를 읽고, 결재만 한다.
- **부서**가 일을 받아 전문가에게 나눠 맡기고, 결과를 모아 보고한다.
- 외부로 나가는 일(발송·게시·광고 집행·법원 제출)은 결재 없이는 하지 않는다.

## 1. 구성 요소

| 구성 | 정의 | 구현 |
|---|---|---|
| 대표 | 변호사 | 업무 보드의 지시 입력, 보고서함, 결재함 |
| 비서실장 | 지시를 읽고 맡을 부서를 고른다. 여러 부서가 필요하면 순서를 정한다 | **신규, 2단계**. 담당 선택지 중 하나. 별도 세션 1회. 부서 목록과 각 부서 설명만 받는다 |
| 부서 | 부서장 1 + 전문가 여러 명 + 부서 규칙 파일 1개 | 사무소 전체에 한 벌인 `teams.yaml`의 부서 항목 |
| 부서장 | 일을 나누고, 전문가를 고르고, 결과가 충분한지 판단해 취합한다 | **앱 내장 부서장 지침** + 부서별 추가 지침(선택). 전문가를 부서장으로 쓰지 않는다. v0.1.357의 부서장 세션 + `assign_members` |
| 전문가(직원) | 역할 하나, 산출물 형식 하나. 다른 전문가를 부르지 않는다 | 전문가 md 파일 1개 = 하위 카드 1장의 독립 세션 |
| 부서 규칙 | 부서 공통 규칙(읽을 파일, 광고 법규, 서식 등) | **신규**. 앱이 전문가 지침 앞에 붙여 넣는다 |

전문가끼리는 일을 주고받지 않는다. 나누고 모으는 일은 부서장이, 부서 사이의 연결은 비서실장이 한다.

## 2. 동작 흐름

1. 대표가 업무 보드에 지시를 올리고 담당 **부서**를 고른다(기본). 지시 창구는 업무 보드뿐이다. 대화창의 「○○부서에 맡겨」는 2단계에서 보드 카드를 만드는 바로가기로만 추가한다.
2. 2단계부터 담당에 **비서실장에게 맡김**을 고를 수 있다. 그러면 비서실장이 부서를 고른다. 여러 부서가 필요하면 부서 지시 여러 장을 `after` 순서로 만든다. 앞 부서의 최종 보고서는 뒤 부서 지시의 참고자료로 들어간다.
3. 부서장이 지시를 읽는다. 혼자 처리할 수 있으면 직접 보고서를 쓴다. 아니면 `assign_members`로 전문가별 하위 카드를 만든다.
4. 전문가는 각자 독립 세션에서 일한다. 받는 것은 ① 부서 규칙 ② 자기 지침 ③ 정해진 양식의 지시문 ④ 앞 단계 하위 업무의 보고서뿐이다.
5. 하위 업무가 모두 끝나면 부서장이 다시 실행되어 보고서를 검토·취합한다. 부족하면 같은 전문가에게 보완 하위 업무를 한 번 더 낼 수 있다(최대 1회).
6. 최종 보고서는 v0.1.357과 같이 보고서함 또는 결재함으로 간다.

## 3. 전문가 정의 파일

### 읽는 위치와 우선순위

같은 이름이면 위가 이긴다 (Claude Code 공식 우선순위와 같음).

1. `~/.claude/agents/` (`CLAUDE_CONFIG_DIR` 지정 시 그 아래)
2. 설치된 플러그인의 `agents/` — 이름은 `플러그인명:전문가명`

v0.1.357은 1번만 읽는다. 2번을 추가한다. SSH 작업 폴더는 그 서버의 같은 위치를 읽는다.

작업 폴더의 `.claude/agents/`(프로젝트 전문가)는 레거시라 지원하지 않는다.

### 반영할 머리말 항목

| 항목 | v0.1.357 | 변경 |
|---|---|---|
| `name`, `description` | 반영 | 유지 |
| 본문(지침) | 반영 | 앞에 부서 규칙을 붙인다 |
| `model` | **무시** | 반영. 비용 조절의 핵심 |
| `effort` | 무시 | 반영 |
| `tools`, `disallowedTools` | 무시 (전원 `tools: []`) | 부서 허용 도구와 **교집합**으로 반영 |
| `maxTurns` | 무시 (일괄 40) | 반영, 상한 40 |
| `permissionMode`, `hooks`, `mcpServers`, `memory`, `isolation` | 무시 | **계속 무시**. 권한·외부 연결은 앱이 정한다 |

전문가 파일은 `~/.claude/agency-agents-adapt/build.py`가 생성한다. 앱은 전문가 파일을 고치지 않는다. 부서 규칙은 앱이 실행할 때 붙인다.

## 4. 부서 정의 (`teams.yaml`)

### 위치

- 부서 정의는 **사무소 전체에 한 벌**이다. 사건 보드마다 두지 않는다.
- 부서를 돌리는 컴퓨터는 **한 대**다. 전문가 파일(`~/.claude/agents/`)이 있는 그 컴퓨터(로컬 또는 SSH 서버)의 `~/.legal-terminal/departments/`에 `teams.yaml`과 `rules/<부서>.md`를 둔다. 다른 PC는 열람·결재만 한다. 실행 담당은 v0.1.357의 「이 PC에서 관리」로 넘긴다.
- v0.1.357의 사건별 `_업무지시/teams.yaml`은 더 읽지 않는다. 사무소 부서 정의가 비어 있을 때 한 번만 「기존 보드 부서 가져오기」를 제안한다.
- 처음에는 부서가 **비어 있다**. 부서 관리 화면의 **제안 구성 불러오기**로 입력 문서의 5개 부서(법률지원·콘텐츠·마케팅·영업·플랫폼운영)를 한 번에 만들 수 있다. 전문가 파일이 없는 부서원은 불러올 때 빼고 알린다.

### 형식

```yaml
teams:
  법률지원:
    color: '#3b6ea5'
    description: 계약 검토, 증거 정리, 사건 요약      # 비서실장이 부서를 고를 때 읽는다
    lead_guide: rules/법률지원-부서장.md              # 선택. 앱 내장 부서장 지침에 덧붙인다
    rules: rules/법률지원.md                          # 신규. departments 폴더 기준 경로
    tools:                                           # 신규. 도구별 허용 · 먼저 묻기 · 끔
      korean-law: allow
      legal-books: allow
      jurisupport-write: ask                         # 쓰기 도구는 ask 이상 불가
    agents: [lawpid-contract-review, lawpid-evidence-synthesis, lawpid-exec-summary]
```

- `tools`에 적지 않은 도구는 `off`다. `allow`는 읽기 전용 도구에만 쓸 수 있다. 쓰기·외부 실행 도구는 `ask`(결재함) 또는 `off`만 가능하다.
- `teams.yaml`을 저장할 때마다 이전 판을 보관한다. 부서 관리 화면에서 변경 이력을 보고 이전 판으로 되돌린다.

- `description`이 겹치면 비서실장이 잘못 고른다. 부서 설명끼리, 부서 안 전문가 설명끼리 겹치지 않게 저장 시 경고한다.
- 부서원 이름이 정의 파일에 없으면 v0.1.357처럼 지시를 막는다.

## 5. 부서장이 넘기는 지시문 양식

`assign_members`의 각 항목을 자유 문장 대신 아래 필드로 받는다. 빠지면 도구 호출을 거절한다.

| 필드 | 필수 | 내용 |
|---|---|---|
| `member` | 필수 | 전문가 이름 |
| `goal` | 필수 | 이 하위 업무로 얻을 결과 한 문장 |
| `sources` | 필수 | 읽을 파일 경로 목록 (`case_list` 기준 상대 경로) |
| `scope` | 필수 | 할 일과 하지 않을 일 |
| `output` | 필수 | 산출물 형식 (예: 표, 메모 2쪽, 서면 초안 md) |
| `due` | 선택 | 기한 |
| `after` | 선택 | 먼저 끝나야 하는 항목 번호 |

## 6. 도구와 권한

| 구분 | 누가 | 결재 |
|---|---|---|
| 사건 폴더 읽기, 새 초안 쓰기 | 전원 | 없음 (v0.1.357과 같음) |
| 법률 근거 조회: korean-law MCP, `legal-books`, `lbox-search` | 부서 `tools`에 `allow`로 넣은 부서 | 없음 (읽기 전용) |
| JuriSupport 할일 조회 | 허용 범위 내 | 카드 버튼 (v0.1.357과 같음) |
| 기존 파일 덮어쓰기, 명령 실행, 쓰기 MCP | 부서 `tools`에 `ask`로 넣은 부서 | 결재함. `off`면 요청 자체를 못 한다 |
| 발송·게시·광고 집행·법원 제출 | 없음 | 하지 않는다. 초안과 계획까지만 |

- 법률 판단 근거는 위 세 출처로 확인한 것만 쓴다. 보고서에 출처를 표기하게 한다.
- v0.1.357은 전문가가 korean-law를 전혀 쓸 수 없다. 1단계에서 앱 쪽 MCP로 연결한다.
- `legal-books`, `lbox-search`는 스킬(스크립트·브라우저)이라 그대로는 못 쓴다. 앱이 읽기 전용 MCP 도구로 감싸서 제공한다. `lbox-search`는 크롬 세션이 필요해 2단계로 미룬다.
- 전문가 세션에는 `Agent` 도구를 주지 않는다. 공식 문서상 서브에이전트는 기본적으로 하위 에이전트를 부를 수 있으므로, 「전문가는 다른 전문가를 부르지 않는다」는 앱이 도구 목록으로 강제한다.

## 7. 비용

- 전문가마다 별도 모델 호출이다. 부서장 지침에 「필요한 전문가만 고른다」를 넣고, 부서 전원을 기본으로 돌리지 않는다.
- 전문가 `model`을 반영한다 (예: 정리·요약은 sonnet/haiku, 법리 판단은 opus).
- 카드 상세에 하위 업무별 토큰·소요시간을 표시한다 (SDK `task_progress`의 usage 사용).
- 지시 1건과 부서 월간 사용량에 **경고선**을 둔다. 넘으면 카드와 부서에 경고를 표시하고 일은 계속한다.
- **강제 정지선**(SDK `maxBudgetUsd`)은 2주 실측 후 정한다. 정하면 넘을 때 **확인 필요**로 멈춘다. 사용량 집계가 늦게 들어오므로 정지는 다소 늦을 수 있다.

| 플러그인 전문가 | SSH 서버의 Claude 설정 폴더(`CLAUDE_CONFIG_DIR` 또는 `~/.claude`)에서 `plugins/installed_plugins.json`과 `settings.json`의 켜 둔 플러그인을 읽는다. 설치 경로가 그 설정 폴더의 `plugins/` 아래에 있는 플러그인만 따른다 |
| korean-law | 서버에 설치·활성화된 korean-law 플러그인의 서버 경로를 원격 Claude CLI에 넘긴다. API 키는 서버의 플러그인 설정을 그대로 쓴다 |
| 원격 실행 옵션 | 원격 CLI로 넘기는 옵션 허용 목록에 전문가 `--model`·`--effort`·`--max-turns`(1~40), 정지선 `--max-budget-usd`, korean-law `--plugin-dir`(`plugins/cache/…/korean-law/…`만), 플러그인 전문가 이름(`플러그인:이름`)을 값 검사와 함께 추가했다. `--strict-mcp-config`는 korean-law를 붙일 때만 빠질 수 있다 |
| 버그 수정 | 1·2단계 이후 SSH 보드에서 전문가에 `model`·`effort`가 있거나 정지선이 걸리면 「지원하지 않는 원격 보드 SDK 실행 옵션」으로 실패하던 문제를 위 허용 목록으로 고쳤다 |

### 검증

`npm run verify:work-board-remote-runner`: SSH2 채널과 실제 Claude CLI로 서버의 가짜 korean-law 플러그인 MCP 호출, 플러그인 전문가·모델·정지선 전달, 허용 목록 밖 옵션 차단 확인. `npm run verify:work-board-ssh`: 실제 SFTP로 켜 둔 플러그인만 읽기, 설정 폴더 밖 설치 경로 무시, SSH 서버의 부서 저장·이력·사용량 확인(v0.1.357부터 깨져 있던 SSH 테스트 단언도 고침).

### 남은 확인

- 실제 SSH 서버의 korean-law 플러그인이 서버의 API 키로 조회하는지는 실제 업무로 확인해야 한다.
