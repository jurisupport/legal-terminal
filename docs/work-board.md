# 업무지시 보드

사건을 열고 상단의 **업무 보드**를 누르면 해당 작업 폴더의 보드가 열린다. **일괄 지시**에서 지시를 줄 또는 빈 줄로 구분해 붙여 넣고 각 지시의 담당자, 기한, 검토자와 결과 처리 방식을 선택한다. 에이전트 입력창에 작성한 내용도 **일괄 지시**로 가져올 수 있다. 작업 폴더 선택기에서 다른 사건의 보드로 이동한다.

기본 저장 위치는 사건 작업 폴더의 `_업무지시`다. 지시서와 보고서는 각각 `<id>.md`, `<id>.report.md`에 저장된다. 검토를 사용하면 `<id>.review.md`가 추가된다. 같은 폴더의 `_보고서양식.md`를 편집하면 다음 지시부터 적용된다. 부서는 사무소 전체에 한 벌이며, 업무를 실행하는 컴퓨터의 `~/.legal-terminal/departments/teams.yaml`에 저장된다. 조직도의 **부서 관리**에서 부서 설명·부서원·부서 규칙·부서장 추가 지침·도구 권한·비용 경고선을 고친다. 저장할 때마다 이전 판이 보관되어 되돌릴 수 있다. 담당에서 **자동 배분**(담당을 고르지 않은 새 지시의 기본값)은 비서실장이 맡을 부서와 순서를 정하고 부서 보고서를 모아 보고한다. 부서가 없거나 맞는 부서가 없으면 기본 세션이 직접 처리한다. 에이전트 입력창의 **부서에 맡기기**는 작성한 내용을 지시 하나로 보드에 올린다. 부서 관리의 **정기 업무**는 정해진 시각(한국 시간)에 그 부서 앞으로 카드를 만든다. **매일 할일 점검 추가**로 평일 아침 할일 점검을 바로 등록할 수 있다. 자세한 동작은 `docs/부서-기능정의.md`를 따른다. 담당자 목록은 선택한 작업 폴더가 있는 컴퓨터의 Claude 설정 폴더(`~/.claude/agents/*.md` 또는 `CLAUDE_CONFIG_DIR/agents/*.md`)에서 읽는다.

| 등록할 때 선택 | 결과가 도착하는 곳 | 버튼을 눌렀을 때 |
|---|---|---|
| **보고서 받기** (기본) | 업무가 완료되면 **보고서함**에 미확인으로 표시 | **보고서 확인**은 이 보고서를 읽었다는 기록만 남긴다. 다른 기기에서도 같은 확인 상태가 보인다. 원본 할일을 변경하거나 다음 작업을 실행하지 않는다. |
| **최종안 승인받기** | **결재함** | 문서를 살펴본 뒤 **최종안 승인**을 누르면 해당 지시가 승인·완료된다. 보완이 필요하면 **수정 요청**을 남긴다. |
| **승인 후 실행** | **결재함** | 승인 후 실행할 지시와 허용할 도구를 확인한다. 승인하면 해당 단계가 대기열에 들어가고, 실제 수행이 끝난 뒤 원래 지시가 완료된다. |

새 지시에는 **보고서 받기**가 기본이다. 기존에 결재 대기 중이던 지시는 결재함에서 계속 처리한다. 발송·외부 실행 결과가 불확실하면 실제 처리 결과를 확인한 뒤 진행한다.

**일일 보고**는 한국 시간 기준이다. 앱이 실행 중이면 설정 시각 이후 첫 점검에서 `_일일보고/YYYY-MM-DD.md`와 같은 이름의 HTML을 저장한다. 앱이 꺼진 동안 시각이 지났으면 당일 다시 실행할 때 생성한다. HTML은 브라우저에서 파일 하나로 열 수 있다.

## 보고서를 읽고 추가 업무를 지시할 때

카드 상세에서 **추가 업무 지시**를 누르고 새로 할 일을 적는다. 예를 들어 할일 보고서를 읽은 뒤 “기한 초과 항목의 의뢰인 안내문 초안을 작성해 줘”라고 등록할 수 있다. 등록 당시의 원 지시와 완료된 범위의 보고서 본문이 새 지시의 참고 자료가 된다. 아직 보고서가 없으면 원 지시만 참고한다. 등록 시 복사하는 제목·본문·보고서의 합계 한도는 16만 자다.

추가 업무에는 독립된 카드와 결과가 생긴다. 등록만으로 기존 보고서의 확인 여부, 원 지시의 완료·결재 상태는 바뀌지 않는다. 원 카드에서 추가 지시를 열 수 있고, 새 카드에서 원 업무를 확인할 수 있다. 새 지시의 기본값은 **보고서 받기**다. 할일 원본을 새로 조회하거나 발송을 요청할 때는 새 지시에서 조회 범위 또는 승인 후 실행 내용을 직접 지정한다.

## 다른 PC에서 결재하거나 업무를 관리할 때

같은 업무지시 폴더를 열었을 때 다른 앱이 실행 담당으로 등록되어 있으면 우선 지시와 보고서를 열람할 수 있다. 이 표시는 등록 정보이며 실제 실행 여부를 뜻하지 않는다. 기존 담당 기기에서 수행·검토가 끝났는지 확인하고, 구버전 앱은 종료한다. 동기화 폴더를 사용한다면 양쪽에 변경 사항이 반영된 뒤 **이 PC에서 관리**를 선택한다. SSH에서는 두 기기가 같은 서버의 같은 업무지시 폴더를 열어야 한다.

동시 실행 수와 일일 보고 시각은 현재 PC에 저장된 보드 설정을 따른다. 관리권을 가져온 PC의 결재함에서 보고서와 승인 후 실행 내용을 확인한다. 외부 실행의 결과가 불확실하면 실제 발송·처리 결과부터 확인한다. 현재 계정의 할일 조회 권한이나 외부 실행 승인은 새 기기에서 다시 확인해야 할 수 있다.

업무 카드를 열면 본문·진행 로그·보고서가 보인다. **확인 필요**를 비롯한 실행 전후의 일반 지시는 상세에서 수정하거나 삭제할 수 있다. 수정 후에는 내용을 확인하고 **다시 실행**을 누르면 재수행한다. 할일 검토 지시는 **할일 다시 조회**를 누른다. 삭제를 확정하면 업무가 목록에서 빠지고 지시서와 보고서·검토서가 보드 폴더의 `_보관/<지시 ID>/`에 남는다. 실행 중인 지시, 처리 결과 확인이 필요한 승인 후 실행, 다른 업무가 참조하는 선행 지시에는 가능한 동작과 제한 사유가 표시된다.

## JuriSupport 할일 검토

업무 보드에서 **일괄 지시**를 열고 한 줄로 **할일 검토** 또는 **쥬리서포트 할일 점검하기**, **할일 정리부터 하자** 등을 입력한다. 기본 담당으로 처리할 수 있다. 등록 화면에서 보고서에 포함할 범위를 확인한다. 사건 보드는 연결된 사건을 사용하며, 일반 보드에서 “할일 검토”를 입력하면 현재 계정의 전체 미완료 할일이 미리 선택된다. 등록 버튼 옆에서 보드 폴더에 저장된다는 안내를 확인하고, 필요하면 특정 사건으로 범위를 좁힌다. 범위는 등록할 때 정하므로 조회 도중에는 질문을 받지 않는다.

앱은 로그인된 JuriSupport 계정으로 `list_tasks`를 페이지당 100건씩 끝까지 조회한다. 표준 검토는 앱의 읽기 전용 기능으로 처리하므로 로컬·SSH 보드 모두 Claude 로그인이나 사용자 스킬 설치 없이 보고서를 작성할 수 있다. 원본 할일의 담당자·기한·상태는 유지된다. 2차 검토 담당이 있으면 검토를 거친 후 선택한 결과 처리 방식으로 전달된다.

“쥬리서포트 할일을 정리한다”처럼 담당 에이전트가 수행하는 일반 업무에서도 JuriSupport의 현재 할일을 조회할 수 있다. 담당자가 조회를 요청하면 **확인 필요** 카드에서 사건 또는 전체 미완료 할일을 선택하고 **조회 허용하고 다시 실행**을 누른다. 이 버튼은 해당 지시를 한 번 다시 수행하는 동안 선택한 범위를 읽을 수 있게 한다. 앱이 관리 기기의 로그인으로 MCP 조회를 수행하고 담당자에게 결과를 전달한다. SSH 보드의 담당자도 같은 방법으로 조회한다. 추가 지시에 적은 글은 담당자에게 전달할 업무 내용이며 조회 권한은 카드의 버튼에서 부여한다.

보고서 첫 줄에 한국 시간 기준일, 조회 범위와 미완료 건수를 표시한다. 기한 초과·기한 임박(오늘부터 3일 뒤까지)·담당자 미지정·재확인일 도래·기한 없음을 구분한다. 한 할일이 여러 조건에 해당하면 관련 표마다 표시하며, 총건수는 ID당 한 번만 센다. 개인 할일도 작성자를 담당자로 자동 간주하지 않는다. 일부 페이지만 받았거나 접근 권한 또는 계정이 바뀌면 해당 원인을 표시한다. 중단된 할일 검토는 카드 맨 위에서 범위를 고르고 **할일 다시 조회**를 누른다. 조회 결과가 같은 카드에 나타난다.

결재 카드를 열면 맨 위의 **결재 대상 문서**에서 원문을 열람할 수 있다. Markdown·텍스트는 카드 안에서 읽고, PDF·HWP·HWPX·DOCX 등은 별도 문서 창에서 연다. 창을 닫으면 같은 카드에서 작성 중이던 사유로 승인·반려를 계속할 수 있다. 별도 문서가 없는 지시는 업무 보고서 본문이 결재 대상이다. 보고서 생성 전에 중단된 카드도 **작업 중 읽은 참고 문서**에서 HTML·Markdown 등을 열고 원본을 **다운로드**할 수 있다. HTML 미리보기는 문서의 본문과 표를 오프라인으로 표시한다. 파일별 다운로드는 원본 바이트를 보존한다. 완료된 업무 보고서는 Markdown으로 저장할 수 있다. **확인 필요** 카드에 중단 사유만 있다면 아직 결재할 업무 결과가 없다. 이전 버전에서 “쥬리서포트 할일 점검하기”가 중단된 경우, 상세에서 조회 범위를 확인하고 **할일 다시 조회**를 누르면 기존 지시로 보고서를 작성한다. 일반 할일 재조회 결과는 **보고서함**에서 읽고 **보고서 확인**으로 표시한다. 최종안 승인이나 승인 후 실행을 지정한 지시는 **결재함**에서 결정한다.

## 개발 의뢰의 세 가지 설계 결정

1. **배분기**는 Claude Agent SDK로 지시·검토마다 독립 세션을 만든다. 기존 대화의 대기열과 권한을 상속하지 않는다. 기본 동시 실행 수는 1이다. SSH 사건은 앱이 기존 SSH 연결을 통해 서버의 Claude CLI를 실행한다. 서버에는 Claude CLI와 Python 3가 필요하다. 지시·검토·승인 후 실행에 그 서버의 로그인과 담당자 정의를 사용한다. 서버의 로그인이 만료됐다면 해당 원격 대화 탭의 **로그인** 버튼으로 인증한 뒤 보드에서 실패한 지시를 **다시 실행**으로 재시도한다.
2. **도구 권한**은 앱이 실제 도구를 호출하는 지점에서 검사한다. 일반 지시는 사건 폴더 조회·문서 읽기·새 초안 작성을 할 수 있다. JuriSupport 할일은 카드에서 허용한 범위로 조회한다. 추가 외부 MCP 도구는 신뢰하는 HTTPS 서버를 먼저 등록하고 정확한 도구 이름을 결재해야 한다. 작업 폴더에서 실행할 명령을 결재할 때는 `Bash(명령 전문)`을 사용한다. 위험 도구와 명령 패턴은 앱 사용자 데이터의 `work-boards/<보드 식별값>/tool-policy.json`에서 관리한다. 결재 권한은 지시서가 있는 동기화 폴더와 분리해 보관한다.
3. **원격 변경 감지**는 기존 SSH 파일 연결 풀을 재사용한다. 보드별 주기적 목록 조회와 지시 실행 중 발생하는 상태 이벤트를 사용한다. 파일마다 SSH 감시 프로세스를 띄우지 않는다. 동일한 보드는 한 번에 한 기기가 배분한다. 실행 담당은 보드에서 명시적으로 넘길 수 있다. 서로 연결이 끊긴 복제 폴더에서 같은 보드를 동시에 최초 등록하면 파일 동기화 자체가 배타적 실행을 보장할 수 없다.
